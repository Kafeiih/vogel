## Specs
- S1 (#101): "Add OpenTelemetry tracing: an HTTP server middleware, a pgx tracer (it can compose with the existing pool tracer from #96), River job spans (a middleware next to `requestIDMiddleware`), and outbound clients (Zitadel, Cerbos, S3)."
- S2 (#101): "Propagate W3C `traceparent`/`tracestate` in and out, and carry it through River job metadata like `vogel_request_id`."
- S3 (#101): "Add `trace_id`/`span_id` to log lines (the context-aware handler in `logger/context_handler.go`) and exemplars on the HTTP and pool histograms."
- S4 (#101): "Decide on exporter configuration (OTLP), sampling, and keeping the root module light: ports in dependency-free packages, adapters in subpackages, as the README requires."
- D1: adapters in same-module subpackage `vogel/otel`; root ports import no OTel; tracing optional at every level (no import, `--without tracing`, no endpoint = no-op).
- D2: incoming `traceparent` untrusted by default: new root trace + span link to the remote parent; `WithTrustedPropagation()` continues the parent.
- D3: error JSON adds `request_id` (same value as today's `trace_id`); `trace_id` deprecated in v0.12.0, removed in v0.13.0.
- D4: `otel.Setup(ctx, otel.Config{...})` explicit (library never reads env); boilerplate reads standard OTEL_EXPORTER_OTLP_ENDPOINT / OTEL_SERVICE_NAME / OTEL_TRACES_SAMPLER_ARG, validated with config.Errors; off without endpoint; OTLP HTTP/protobuf; ParentBased(TraceIDRatio) default 0.1; flush on shutdown after HTTP server and River queue.
